## 0. วิธีอ่านเอกสารนี้

ผมวาง schema โดยเทียบสองอย่างเข้าหากัน คือ **ฟิลด์ที่ design เรียกใช้จริง** กับ **คอลัมน์ที่มีอยู่ในชีต** แล้วดูว่าตรงกันตรงไหน ขาดตรงไหน

ผลออกมาเป็นสามกอง
- **มีในชีตแล้ว ใช้ได้เลย** — ส่วนใหญ่
- **design ต้องใช้ แต่ชีตยังไม่มี** — ต้องเพิ่มคอลัมน์ ดูข้อ 6 มี 11 คอลัมน์ แต่บังคับจริง ๆ แค่ 3
- **ไม่ต้องเก็บ เพราะคำนวณเอาได้** — เช่นส่วนลดของ SET ดูข้อ 5

> **ข้อตกลงเรื่องตัวสะกด:** ไฟล์ JSON ฝั่งเนื้อหาใช้ `camelCase` เพราะฝั่ง Next.js เป็น TypeScript ส่วน API ของ Go ใช้ `snake_case` ตามที่ตกลงไว้ในเอกสาร requirement สองอันนี้เป็นคนละชั้นกัน ไม่ต้องทำให้เหมือนกัน

## 2. Course

```ts
type Course = {
  // ── ตัวระบุ ──────────────────────────────────────────────
  slug: string                 // "biocontest-ku"  ใช้เป็น URL ห้ามเปลี่ยนหลังขึ้นเว็บ
  title: string                // ชื่อสั้นบนการ์ด  "Biocontest ม.เกษตรศาสตร์"
  fullTitle?: string           // ชื่อยาวบนหัวหน้า detail ถ้าไม่ใส่ใช้ title
  tagline: string              // คำโปรยหนึ่งบรรทัดบนการ์ด

  // ── การจัดหมวด ───────────────────────────────────────────
  group: 'prathom' | 'mton' | 'mplai'
  category: string             // หมวดหมู่จากชีต ค่าเดียว · หัวข้อแถบใน Course List, ตัวกรอง "ทุกหมวดหมู่" และป้ายบนการ์ด
  subject: 'science' | 'biology' | 'chemistry' | 'physics' | 'math' | 'applied_science'
                               // map จากคอลัมน์ วิชา: วิทยาศาสตร์ → science · ชีววิทยา → biology
                               // เคมี → chemistry · ฟิสิกส์ → physics · คณิตศาสตร์ → math
                               // วิทยาศาสตร์ประยุกต์ → applied_science (A-Level วิทย์ประยุกต์)

  // ── ผู้สอน ───────────────────────────────────────────────
  instructorSlug: string       // อ้างไปที่ site.instructors

  // ── สถานะและราคา ─────────────────────────────────────────
  price: number                // บาท จำนวนเต็ม
  compareAtPrice?: number      // ราคาก่อนลด ใช้ขีดฆ่า ไม่ใส่ = ไม่โชว์ขีดฆ่า
  priceNote?: string           // "ราคาพิเศษช่วงเปิดคอร์ส"
  saleMode: 'standalone_and_set' | 'standalone_only'

  // ── ตัวเลขที่โชว์เป็นแถวสถิติ ───────────────────────────
  stats: {
    questionCount?: number     // จำนวนข้อสอบ
    pdfPages?: number | { min: number; max: number }   // เป็นช่วงได้
    videoHours?: number
  }

  // ── เนื้อหา ──────────────────────────────────────────────
  chapters: { title: string }[]   // "คลิปที่ 1 · เซลล์และกระบวนการในเซลล์"
  forWho: string[]                // การ์ด "คอร์สนี้เหมาะกับใคร"
  contentPoints: string[]         // รายการเนื้อหาจากชีต
  deliverables: string            // "ไฟล์ PDF + คลิปวิดีโอ (ไม่จำกัดอายุ)"
  faqs?: { q: string; a: string }[]   // ไม่ใส่ = ใช้ FAQ กลางจาก site.json

  // ── สื่อ ─────────────────────────────────────────────────
  coverImage?: string          // "covers/biocontest-ku.jpg" ไม่ใส่ = ใช้ลายเส้นแทน
  previewVideoUrl?: string     // ลิงก์ YouTube คลิปตัวอย่าง ไม่ใส่ = ซ่อนบล็อกนั้น

  // ── ความสัมพันธ์ ─────────────────────────────────────────
  setCodes: string[]           // ["BC-01","BC-02"] ตรวจกับ sets.json ตอน build
}
```

## 6. สิ่งที่คำนวณตอน build — ห้ามเก็บในไฟล์

นี่คือหัวใจที่ทำให้ตัวเลขบนเว็บไม่มีวันขัดกันเอง

| ค่า | สูตร | ใช้ที่ไหน |
|---|---|---|
| `set.compareAtPrice` | รวม `price` ของทุกคอร์สใน `courseSlugs` | ราคาขีดฆ่าบนการ์ดเซ็ต |
| `set.savings` | `compareAtPrice - price` | "ประหยัด 199.-" |
| `set.savingsPercent` | `savings / compareAtPrice` | ป้ายเปอร์เซ็นต์ |
| `set.showSavingsBadge` | `savings >= 100 หรือ percent >= 10%` | ซ่อนป้ายของเซ็ตที่ประหยัด 1% |
| `set.totals` | รวม `videoHours` / `pdfPages` / `questionCount` ของสมาชิก | "รวม 2 คอร์ส VDO 20 ชม. · PDF 166 หน้า" |
| `set.courseCount` | `courseSlugs.length` | การ์ดเซ็ต |
| `course.inSets` | เซ็ตทุกตัวที่มีคอร์สนี้ เรียงจากประหยัดมากไปน้อย | กล่อง "ซื้อเป็น SET คุ้มกว่า" |
| `course.chapterCount` | `chapters.length` | "4 คลิป · 100 ข้อ" |
| `counts` | จำนวนคอร์สต่อกลุ่มและต่อ track | ตัวเลขบนปุ่มแท็บและ dropdown |

**ราคาปกติ ประหยัด (บาท) และประหยัด (%) ที่พิมพ์ไว้ในชีต ไม่ต้องดึงมาใช้** แต่ให้สคริปต์คำนวณแล้วเทียบกับที่พิมพ์ไว้ ถ้าไม่ตรงให้เตือน จะได้จับความผิดพลาดในชีตให้คุณด้วย

## 7. คอลัมน์ที่ต้องเพิ่มในชีต

design เรียกใช้ฟิลด์ที่ชีตยังไม่มีอยู่ 11 ตัว แต่**บังคับจริง ๆ แค่ 3 ตัวแรก** ที่เหลือถ้าไม่ใส่ก็มีทางถอยให้แล้ว เว็บยังขึ้นได้

### ต้องมี

| คอลัมน์ | ทำไมถึงขาดไม่ได้ | ตัวอย่าง |
|---|---|---|
| **slug** | ใช้เป็น URL ถ้าไม่มีต้องใช้ URL ภาษาไทยซึ่งกลายเป็นรหัสยาวตอนก๊อปแชร์ และเปลี่ยนทีหลังไม่ได้เพราะ Google จำไว้แล้ว | `biocontest-ku` |
| **คำโปรยสั้น** | การ์ดทุกใบในทั้งสามหน้าต้องใช้ ตอนนี้ชีตมีแต่ช่องรายละเอียดยาว ซึ่งยาวเกินกว่าจะใส่ในการ์ด | "เฉลยข้อสอบแข่งขัน 100 ข้อ ทีละข้อพร้อมวิธีคิด" |
| **สถานะ** | design มีทั้ง "เรียนได้ทันที" และ "เริ่ม 1 ต.ค. 69" ถ้าไม่มีคอลัมน์นี้ ทุกคอร์สจะถือว่าเปิดหมด | `เปิดแล้ว` หรือวันที่ |

### ใส่ได้ก็ดี ไม่ใส่ก็ยังขึ้นเว็บได้

| คอลัมน์ | ถ้าไม่ใส่จะเป็นยังไง |
|---|---|
| ราคาก่อนลด | ไม่โชว์ราคาขีดฆ่า เหลือราคาเดียว — **แนะนำให้ใส่** เพราะ design วางให้มีทุกการ์ด และราคาขีดฆ่าช่วยการตัดสินใจมาก |
| หมายเหตุราคา | ไม่โชว์บรรทัด "ราคาพิเศษช่วงเปิดคอร์ส" |
| ชื่อยาว (หัวหน้า detail) | ใช้ชื่อสั้นแทน |
| รายการคลิป | ซ่อนส่วน "เนื้อหาในคอร์ส" ทั้งบล็อก |
| ลิงก์ YouTube คลิปตัวอย่าง | ซ่อนบล็อกคลิปตัวอย่าง และซ่อนปุ่ม "ดูคลิปตัวอย่างฟรี" |
| คอร์สขายดี (อันดับ) | ส่วน "คอร์สขายดี" หน้าแรกใช้สามคอร์สแรกของ ม.ปลาย ไปก่อน |
| รูปปก | ใช้ลายเส้นแทนเหมือนใน design ซึ่งดูโอเคอยู่แล้ว |

**คำแนะนำ:** ถ้ามีเวลาจำกัด ใส่แค่ slug คำโปรย สถานะ และราคาก่อนลด แค่สี่ตัวนี้ก็ได้เว็บที่ดูสมบูรณ์แล้ว ที่เหลือทยอยเติมได้โดยไม่ต้องแก้โค้ด

## 8. เรื่องที่ design กับชีตไม่ตรงกัน และผมเสนอทางออก

### 8.1 รายการคลิปยังไม่มีในชีตเลย

design หน้า detail มีบล็อก "เนื้อหาในคอร์ส" ที่ลิสต์คลิปที่ 1 ถึง 4 แต่ชีตมีแค่จำนวนชั่วโมงรวม ไม่มีรายชื่อคลิป

บล็อกนี้เป็นส่วนที่คนดูก่อนตัดสินใจซื้อ เพราะมันตอบว่า "จ่ายไปแล้วได้เรียนอะไรบ้าง" ถ้าไม่มี หน้า detail จะบางลงพอสมควร แต่ก็ยังขายได้เพราะมีตัวเลขสถิติกับส่วนเหมาะกับใครอยู่

**ทางออก:** ทำเป็นคอลัมน์เดียวในชีต ใส่ชื่อคลิปคั่นด้วย • แบบเดียวกับคอลัมน์อื่นที่คุณทำอยู่แล้ว ไม่ต้องมีตารางแยก แล้วค่อยทยอยกรอกทีหลังได้ คอร์สไหนยังไม่กรอกก็ซ่อนบล็อกนั้นไป

### 8.2 design เขียนว่ารับชำระเงินแล้ว แต่เฟส 1 ยังไม่มี

จุดที่ขัดกับเฟส 1 มีสี่จุด ต้องแก้ข้อความก่อนขึ้นจริง ไม่งั้นลูกค้าจะงง

| ที่ไหน | design เขียนว่า | ความจริงในเฟส 1 |
|---|---|---|
| footer ทุกหน้า | "ชำระเงินผ่านโอนธนาคาร · พร้อมเพย์ · บัตรเครดิต" | ยังไม่มีระบบจ่ายเงิน ต้องเอาออกหรือเปลี่ยนเป็น "สอบถามและสมัครผ่าน LINE" |
| FAQ หน้า Courses | "จ่ายราคาพรีออเดอร์ แล้วระบบจะปลดล็อกให้อัตโนมัติวันเปิดคอร์ส" | ไม่มีระบบปลดล็อกอัตโนมัติ ต้องเขียนใหม่ว่าทักแอดมินจองไว้ก่อน |
| ปุ่ม "สมัครเรียนเลย" ทุกปุ่ม | ลิงก์ไปหน้า detail | ต้องชี้ไป `/go/contact` แล้วเด้งเข้า LINE OA พร้อมข้อความตั้งต้น |
| ปุ่ม "เข้าสู่ระบบ" | มีอยู่บน header | เฟส 2 ค่อยมี เฟสนี้ซ่อนไว้ก่อน |

### 8.3 ชื่อครูไม่ตรงกัน

ชีตเขียน "ครูพี่หนาม" design เขียน "ครูหนาม" ต้องเลือกอันเดียวแล้วใช้ให้ตรงกันทั้งเว็บ ผมจะใช้ตามที่คุณบอกมา

### 8.4 ข้อมูลตัวอย่างใน design ไม่ใช่คอร์สจริง

โค้ดใน design มีคอร์สอย่าง "พันธุศาสตร์ ม.4 เข้มข้น" และ "TCAS ชีวะ สรุปก่อนสอบ 30 วัน" ซึ่งไม่มีในชีต เข้าใจว่าเป็นข้อมูลสมมติเพื่อให้เห็นหน้าตา ไม่ใช่ปัญหา แต่หมายความว่าตัวเลือกใน dropdown ต้องสร้างจากชีตจริง ไม่ใช่ก๊อปมาจาก design

อีกจุดคือ design ใส่ `O-NET` ไว้ในตัวเลือกของกลุ่มประถม แต่ในชีตกลุ่มประถมไม่มีคอร์ส O-NET เลย มีแค่หมวดประถมกับสอบเข้า ม.1

## 9. การตรวจข้อมูลตอน build

สคริปต์ต้องหยุดและบอกว่าผิดแถวไหน เมื่อเจอ

**หยุดทันที**
- `slug` ซ้ำ หรือว่าง
- `group` / `subject` / `saleMode` มีค่านอกรายการ
- `price` ว่างหรือไม่ใช่ตัวเลข
- `courseSlugs` ใน sets.json ชี้ไปคอร์สที่ไม่มีอยู่
- `setCodes` ในคอร์ส ชี้ไปเซ็ตที่ไม่มีอยู่
- ความสัมพันธ์สองทางไม่ตรงกัน คอร์ส A บอกว่าอยู่เซ็ต X แต่เซ็ต X ไม่มีคอร์ส A
- คอร์สที่ `saleMode` เป็น `standalone_only` แต่มี `setCodes`
- `instructorSlug` ไม่มีใน site.json
- ราคาเซ็ตแพงกว่าหรือเท่ากับราคารวมคอร์สเดี่ยว

**เตือนแต่ไม่หยุด**
- หมวดหมู่ที่ไม่เคยเห็นมาก่อน เพราะคุณอาจเพิ่มของใหม่จริง
- ราคาที่คำนวณได้ไม่ตรงกับคอลัมน์ราคาปกติในชีต
- คอร์สที่ไม่มี `coverImage`, `tagline`, หรือ `chapters`
- `compareAtPrice` น้อยกว่าหรือเท่ากับ `price`

จุดที่พังง่ายที่สุดคือชีตเชื่อมสองตารางด้วย**ชื่อคอร์สเป็นข้อความ** เว้นวรรคเกินหนึ่งตัวก็หลุด พอมี `slug` แล้วควรเปลี่ยนคอลัมน์ "คอร์สที่รวม" ในชีต SET ให้ใส่ slug แทนชื่อ จะปลอดภัยกว่ามาก ถ้าอยากเก็บชื่อไทยไว้อ่านง่าย ก็ใส่ทั้งสองคอลัมน์แล้วให้สคริปต์เช็กว่าตรงกัน

## 10. ผลตรวจข้อมูลจริงในชีต (27 ก.ย. 2569 หลังเพิ่ม slug)

รันการตรวจตามข้อ 9 กับข้อมูลทั้งหมด 44 คอร์ส 27 เซ็ต **ไม่มีข้อผิดพลาดเลย**

| สิ่งที่ตรวจ | ผล |

| slug ครบทุกแถว ไม่มีช่องว่าง | ผ่าน 71/71 |
| slug ไม่ซ้ำกัน (รวมข้ามสองตาราง) | ผ่าน |
| รูปแบบ slug เป็น a-z 0-9 คั่นขีดกลาง | ผ่าน ไม่มีอักษรไทย ตัวพิมพ์ใหญ่ หรือขีดล่าง |
| slug เซ็ตลงท้าย `-bundle` ทุกตัว | ผ่าน จึงไม่มีทางชนกับ slug คอร์ส |
| ราคาปกติ = ผลรวมราคาคอร์สสมาชิก | ผ่าน 27/27 |
| จำนวนคอร์ส = จำนวนรายการที่ระบุ | ผ่าน 27/27 |
| ประหยัด (บาท) = ราคาปกติ − ราคาเซ็ต | ผ่าน 27/27 |
| ประหยัด (%) ตรงกับที่คำนวณ | ผ่าน 27/27 |

| ชื่อคอร์สไม่ซ้ำ | ผ่าน จึงยังเชื่อมสองตารางด้วยชื่อได้ชั่วคราว |

เรื่องเดียวที่ต้องแก้คือ **ฝั่งเอกสารนี้ ไม่ใช่ฝั่งชีต**: คอลัมน์ วิชา มี 6 ค่าไม่ใช่ 5 — แถว 38 `A-Level วิทย์ประยุกต์` ใช้ `วิทยาศาสตร์ประยุกต์` ผมเพิ่ม `applied_science` ลงใน enum ของ `subject` ในข้อ 2 แล้ว

จำนวนที่นับได้ตรงกับแท็บ "คำอธิบายสี" ทุกช่อง: ประถม 8 คอร์ส 10 เซ็ต · ม.ต้น 12 คอร์ส 6 เซ็ต · ม.ปลาย 24 คอร์ส 11 เซ็ต
